## 1. 已完成的关键改动（本地仓库分支：`fusionrag_unified_pipeline`）

### 1.1 纠正 v2 语义：chunk overlay 不要求与 prefix 连续
背景：demo C 经常触发 `non_contiguous_chunk_span`，原因是旧逻辑要求 `chunk_plan.start_token == prefix_hicache_len`，不符合 `full.md`“chunk_plan 是显式区间 overlay”的契约。

改动：
- `python/sglang/srt/fusionrag_plan.py:select_prefix_compatible_chunk_hits`
  - 改为：不再因为 prefix/区间不连续而裁剪 chunk hits，直接认为命中的 chunk spans 可用（gap 由 prefill 补齐）。
- `python/sglang/test/test_fusionrag_params.py` 相应测试更新为 v2 语义。

### 1.2 修复 output-only logprob 被误判为 input-logprob 的降级
背景：`return_logprob=true, logprob_start_len=-1`（只要输出 logprob）不应触发 `input_logprob_cache_hit_unsupported`。

改动：
- `python/sglang/srt/managers/schedule_batch.py:requests_input_logprobs`
  - 仅当真的请求 prompt 内 logprob 时返回 True。
- `python/sglang/srt/managers/schedule_batch.py:apply_fusionrag_runtime_guards`
  - recompute 禁用逻辑仅对“input logprob”生效，output-only logprob 允许 recompute。

### 1.3 kv_gen 保存区间：按 chunk_plan 目标区间保存（而非整段 prompt）
背景：demo B/C/D 依赖“只保存目标 doc span”的 chunk cache；旧逻辑可能整段保存导致 span/layout 不一致与 `non_contiguous_chunk_span`。

改动：
- `python/sglang/srt/mem_cache/fusionrag_cache.py:cache_finished_req`
  - kv_gen 保存时从 plan 的 `chunk_plan` 中选择 target doc/chunk 对应的 `[start_token,end_token)` 作为保存 span；
  - raw/preprocess 都按该 span 生成 key、写盘与插入索引（共享 KV 只读，request-local 覆盖写）。

### 1.4 让 `import sglang` 更轻量，避免 unit tests 被前端依赖卡死
改动：
- `python/sglang/__init__.py`：将大量前端 API 改为 `LazyImport`，避免强依赖 IPython 等。
- `python/sglang/utils.py`：`IPython.display` 改为可选依赖（缺失时不报错）。

### 1.5 demo C 更新：动态计算 token 坐标
改动：
- `next-to-do/demo.md`：补充 sa1 侧用 tokenizer 计算 `prefix_tokens=P` / `total_tokens`，避免写死 start/end。

### 1.6 新增一键脚本：sa1 上跑 A/B/C/D
新增：
- `next-to-do/run_demo_sa1.sh`
  - 无 `jq` 依赖（只用 curl/rg/python）；
  - C 用例会先 kv_gen 预生成匹配的 preprocess chunk，再发在线 generate 验证 chunk hit + recompute。

## 3. 已知限制/风险（仍需后续 agent 处理/确认）
1. `input logprob + cache hit` 当前仍不支持：会降级 `input_logprob_cache_hit_unsupported`（handoff 里已说明）。是否接受需产品/调用方确认。
2. preprocess chunk cache 偶发 `unsupport layout detected` 警告：疑似旧 artifact/shape 不兼容；需要做 key/version 或清理策略。
3. demo C 的“prefill_tokens>0”并非总能稳定观察（取决于 chunk span 覆盖比例）；如需要严格体现“混合路径”，建议构造 chunk_plan 只覆盖 doc 子区间，确保 gap 明显存在。
